# Essay 随笔界面与使用指南

Essay 是面向思想随笔、评论和长篇论证的文章布局。它以文字为中心，用纸张感背景、衬线字体、留白和少量结构化组件组织阅读节奏。

**`essay: true` 切换的是文章布局，不只是字体。** 未开启的博客仍使用原主题布局。

- 实际示例：[`future_ai/index.mdx`](../src/content/blog/future_ai/index.mdx)，页面路径 `/blog/future_ai`。
- 组件属性与示例：[MDX Essay System](../src/components/essay/README.md)。
- 实施过程与测试记录：[文件变更说明](./future-ai-changes.md)。

本文是仓库中的使用说明，放在根目录 `docs/`，不会自动发布到网站的 `/docs` 内容集合。

## 1. 界面结构

```text
站点顶部导航（沿用原主题）

← 全部文章                         思想随笔 / 发布日期
───────────────────────────────────────────────────
阅读路径
01 第一阶段    02 第二阶段    03 第三阶段
───────────────────────────────────────────────────

英文眉题
文章主标题
开篇引言
───────────────────────────────────────────────────

正文                         最大宽度 720px
概念 / 摘记

    图表 / 公式              最大可扩展至 960px

01 / 推理阶段
章节标题
正文……

▸ 本节英文原文               默认折叠

───────────────────────────────────────────────────
回到开篇 ↑                         更新日期
版权 / 推荐文章 / 评论

站点 Footer（沿用原主题）
```

正文居中，不保留右侧目录占位。宽组件在屏幕空间足够时突破正文宽度，手机端回到单栏。

## 2. 与原布局的区别

| 项目           | 原博客布局                   | Essay 布局                                               |
| -------------- | ---------------------------- | -------------------------------------------------------- |
| 阅读结构       | 正文与侧栏共同分配空间       | 居中单栏，正文最大 720px                                 |
| 宽视觉内容     | 受原正文容器约束             | 公式和时代对比最大 960px                                 |
| 页面底色       | 主题背景与强调色渐变         | 暖白纸张色，深色模式为暖深灰；无原有强调色渐变           |
| 正文与组件字体 | 原主题排版                   | 衬线字体，主要辅助文字 13–14px                           |
| 开篇           | 自动展示标题、摘要和可选封面 | 在 MDX 中用 `EssayLead` 编写文字式开篇                   |
| 封面图         | 配置后展示于文章顶部         | 不在文章顶部展示；保留列表与分享用途                     |
| 目录           | 桌面侧栏，手机可展开         | 顶部阅读路径，只收集 Markdown 二级标题                   |
| 文章信息       | 日期、阅读时长、语言、标签   | 顶部发布日期，页尾更新日期；不展示阅读时长、语言和标签栏 |
| 回到顶部       | 原布局悬浮按钮               | 页尾“回到开篇”文字链接                                   |
| 图片点击放大   | 根据 MediumZoom 配置启用     | 当前没有接入                                             |
| 文章入场动画   | 原布局淡入动画               | 不使用原布局的文章入场动画                               |
| 评论统计信息   | 标题附近                     | 文章底部                                                 |

### 保留的功能

- 站点 Header、Footer 和主题切换。
- 原文章 URL，不新增特殊路由。
- 页面标题、摘要、分享图片等 SEO 元信息。
- 版权、推荐文章、评论；评论仍受 `draft`、`comment` 配置控制。
- 标签等文章数据：不在 Essay 页头显示，不等于删除数据或退出标签集合。

这些取舍是当前实现，并非技术限制。侧栏目录、阅读时长、图片放大等功能可以按需要接入。

## 3. 如何开启

在博客 MDX 的 frontmatter 中添加：

```yaml
essay: true
```

未填写时默认为 `false`，使用原布局。

**只加这个字段不会自动创建开篇、折叠英文或生成概念图。** 布局负责页面骨架，内容组件需要在文章中明确编写。

尤其注意：当前 Essay 布局不会自动把 frontmatter 的 `title` 渲染成可见标题。应在正文中放置一个 `EssayLead`，由它输出唯一的 `h1`。

### 可直接参考的最小 MDX

```mdx
---
title: '一篇关于未来的随笔'
description: '这篇文章讨论技术变化与普通人的选择。'
publishDate: '2026-09-16'
language: 'Chinese'
tags:
  - Essay
essay: true
---

import EssayLead from '@/components/essay/EssayLead.astro'
import Original from '@/components/essay/Original.astro'
import Section from '@/components/essay/Section.astro'

<EssayLead eyebrow="TECHNOLOGY · SOCIETY" title="一篇关于未来的随笔">

这里是开篇引言。

</EssayLead>

这里是正文。

<Section index="01" kicker="The argument">

## 第一个问题

</Section>

这里展开第一阶段的论证。

<Original label="本节英文原文">

The original English text goes here.

</Original>
```

编写时注意：

1. frontmatter 标题用于列表和元信息，`EssayLead.title` 用于页面开篇，建议保持一致。
2. 每篇只放一个 `EssayLead`，不要再写一个 Markdown `#` 主标题。
3. `Section` 内保留 Markdown `##`，Astro 才能提取标题、生成目录锚点。不要把标题改为未定义的 `title` 属性。
4. 组件标签与 Markdown 段落之间保留空行。
5. 日期推荐使用带引号的 ISO 日期，如 `'2026-09-16'`，避免本地时区解析产生日期偏移。
6. 当前模板的界面文案与正文语言标记按中文随笔设计；不是完整的多语言模板。

如果需要指定主标题分行，`EssayLead.title` 也可以传字符串数组，例如 `title={['当人类不再是', '社会运转所必需的']}`。长标题仍需检查手机端效果。

## 4. 内容组件如何配合

| 组件          | 适合放什么                         | 阅读作用                           |
| ------------- | ---------------------------------- | ---------------------------------- |
| `EssayLead`   | 主标题与引言                       | 用文字建立开篇，不依赖大封面       |
| `Section`     | 编号、阶段标签与 Markdown 二级标题 | 标记论证进入新阶段                 |
| `Concept`     | 中英文概念与定义                   | 在需要时澄清术语                   |
| `Aside`       | 少量关键句                         | 提供短暂停顿，不取代完整论证       |
| `Equation`    | TeX 公式与术语解释                 | 呈现模型及其修正                   |
| `Progression` | 时代、群体、杠杆与协调能力比较     | 帮助读者跨阶段比较                 |
| `Scenario`    | 编号、标题与情景正文               | 组织多种可能性，不用彩色卡片堆叠   |
| `Original`    | 一整节英文原文                     | 默认折叠，保留参考而不打断中文阅读 |

推荐保留大量普通正文。公式、时代对比、情景组这类强视觉节点每篇控制在约 3–5 处，不必每一段都放入组件。

`Progression` 的高低条形是定性示意，不是数据图表；当前组件注释包含后 AI 社会的假设，复用到其他主题时应检查其适用性。

英文折叠采用原生 `details/summary`，无需客户端脚本，支持键盘操作。英文仍在 HTML 中；折叠不代表从 RSS、搜索或其他内容消费流程中排除。

## 5. 字体与配色

### 字体分工

- **正文与内容组件：** 使用 `--essay-serif`，优先查找 Noto Serif SC 等宋体／衬线字体。
- **功能性区域：** 使用 `--essay-ui`，例如返回链接、日期、目录链接文字和页尾；内部组件若指定字体则以其规则为准。
- **编号与标签：** 章节编号、目录编号、阅读路径标签等显式使用衬线字体。
- **数学公式：** 保留 KaTeX 自带的数学字体。

组件不再强制等宽字体、全大写或加宽字距。原文自己写成大写的眉题仍保持原样。

这些正文候选字体没有额外配置网页字体下载。浏览器在**读者设备**上选择可用字体，不是在 Vercel 服务器上寻找字体。同一段文字也可能因为字符覆盖范围而使用多个字体。

确认自己的实际字体：Chrome / Edge 中右键检查文字，进入 **Computed → Rendered Fonts（计算样式 → 呈现的字体）**。仅查看 `font-family` 只能看到候选列表。

### 色彩与主题

| 用途     | 浅色      | 深色      |
| -------- | --------- | --------- |
| 背景     | `#F7F5F0` | `#161615` |
| 正文     | `#171717` | `#E8E5DE` |
| 次要文字 | `#68645C` | `#A6A198` |
| 分隔线   | `#D9D5CC` | `#35332F` |
| 强调色   | `#8C2F2B` | `#D58C82` |

主题沿用站点的 `.dark` 切换，不增加独立的随笔主题开关。样式集中在 [`src/assets/styles/essay.css`](../src/assets/styles/essay.css)。

## 6. 移动端与交互

- 正文在窄屏下使用 17px 字号，桌面为 18px，行高为 1.95。
- 三时代对比在小屏改为纵向排列。
- 顶部阅读路径在小屏逐项排列，不使用侧栏抽屉。
- 超长公式在自己的区域内横向滚动，不撑宽整页。
- 英文折叠支持点击及键盘 Enter 操作。
- 导航、折叠和公式区域提供键盘焦点样式。

## 7. 实现文件与调整入口

| 文件                                                              | 职责                                              |
| ----------------------------------------------------------------- | ------------------------------------------------- |
| [`src/content.config.ts`](../src/content.config.ts)               | 声明 `essay` 字段，默认关闭                       |
| [`src/layouts/BlogPost.astro`](../src/layouts/BlogPost.astro)     | 按 `data.essay` 选择新旧布局                      |
| [`src/layouts/EssayPost.astro`](../src/layouts/EssayPost.astro)   | 随笔页骨架、顶部目录、日期与页尾                  |
| [`src/layouts/BaseLayout.astro`](../src/layouts/BaseLayout.astro) | 提供共享站点结构及 `data-appearance='essay'` 标记 |
| [`src/assets/styles/essay.css`](../src/assets/styles/essay.css)   | 字体、宽度、主题、组件和响应式样式                |
| [`src/components/essay/`](../src/components/essay/)               | 八个原生 Astro 内容组件                           |

组件不依赖 React，也不新增 hydration。公式在构建时渲染，目录使用原生锚点。站点已有的主题、评论等功能仍有各自的客户端脚本，不能把整页理解为完全没有 JavaScript。

若要把一篇 Essay 文章改回普通布局，不建议只把开关设为 `false`：还应处理正文中的 `EssayLead`，否则原 Hero 和正文开篇可能重复输出主标题，并检查其他自定义组件的样式。

## 8. 发布前检查

1. 执行 `npm run check` 和 `npm run build`。
2. 检查页面只有一个主标题，且文章标题与列表标题一致。
3. 检查顶部目录能跳转到对应章节。
4. 在手机宽度下检查标题断行、图表和公式滚动。
5. 切换深色模式，检查辅助文字是否清晰。
6. 使用键盘展开英文，确认内容完整。
7. 在真实网络下验证评论等外部集成；不要把页面构建成功等同于所有第三方服务可用。
8. 如果依赖站内搜索，单独确认 Pagefind 索引生成成功。此前环境出现过其平台包安装失败，详情见变更记录。
